## 1. 一张卡是什么

一张卡 ＝ **一个"检查装置会不会骗人"的实验**：

> **把某种真实世界的坏情况注进去 → 看被测装置会不会报警。**
> 不报警 ⇒ **这个装置在这条上是 fail-open**（"没查到"被当成"查过了没问题"）。

卡**不评价装置的代码质量**，只测**它会不会漏**。

## 2. 字段定义

```yaml
id:            # 必填。kebab-case，全库唯一
title:         # 必填。一句话，陈述"被抓住的那种骗法"，不写工具名
catches:       # 必填。1-3 个标签，见 §5
severity:      # 必填。high | medium | low（**按"漏了会怎样"判**：high＝假绿放行；medium＝假红／误导／崩溃冒充；low＝噪音）
deps:          # 必填。注入脚本用到的可执行依赖，如 [bash, node]／[bash, node, powershell]（见 §3）
inject:        # 必填。**只负责造出坏数据**（可执行，见 §3）
run:           # 必填。"怎么把坏数据喂给被测装置"—— 分两行：`本库装置：` 与 `通用：`（见 §3.5）
expect:        # 必填。**可判定的期望观察**（见 §4）
evidence:      # 必填。来自本库 P 段的物证一句话（带真实数字）
source:        # 必填。P 编号或 T 编号（这条从哪来）
applies_to:    # 必填。这类装置/这类代码的特征（用于判断"适不适用"）
verify:        # 必填。实测记录（见 §7，可以是"未实测"——那这张卡不算完成）
limits:        # 选填。明确不适用的情形（防误用）
```

## 3. `inject` 怎么写（**必须能跑，且必须自证生效**）

- 给一段**最小可执行步骤**：可以是 shell／node／python **任一**，**必须在卡里声明依赖**（`deps: [bash, node]`）。
- 步骤要**自包含**：造文件 → 制造坏情况。（"喂给被测装置"是 `run` 的事，见 §3.5）
- 路径一律用占位符 `<tmp>`／`<repo>`，**不许出现任何具体机器的真实路径**。
  > 注（v1.2）：`<subject>` 也是合法占位符 —— 它**不是路径**，是"被测装置入口"，定义见文首 v1.2 说明。
- **不许**要求联网、**不许**要求装第三方包。
- 🔴 **注入后 MUST 自证注入生效**（本契约最贵的一条，2026-10-02 由审查补入）：
  在 `inject` 末尾加一行**独立验证**，证明"坏情况真的存在了"。反例（真实事故）：Windows 的 Git Bash 里 `chmod 000 f` **返回 0 但文件仍可读** ⇒ 注入是**空操作**，实验得不出任何结论，而看卡的人以为测过了。
  > 例：`chmod 000 f` 之后 MUST 跟 `cat f`（应当失败）或 `ls -l` 的**实际输出**；读不了才算注入成功。
  > 平台差异 MUST 处理：Windows 用 `icacls "<file>" /deny "Everyone:(R)"`，且**验证后再跑**、跑完**恢复**。
  > **关系型坏情况**（v1.1 补）：当坏情况是"**两个值不一致**"（文档写的版本 ≠ 现场版本／包内声明的路径 ≠ 实际路径／声明的编号 ≠ 实际最大号）时，**两侧各须被独立观测** —— 读回被注入对象本身 ＋ 取现场真值，只观测一侧不算自证。

## 3.5 `run` 怎么写（**卡与装置的接口必须对得上**）

`run` 说清"**怎么把坏数据喂给被测装置**"，两行：

- **本库装置**：本库 `toys/` 装置用什么参数（**照装置自己的接口写**，不许假定一个它没有的参数）
- **通用**：一个陌生人的装置该怎么接（描述 + 一个示例命令）

> 反例（真实事故）：卡里写 `--config <file>`，而本库对应装置只吃**内联 JSON** ⇒ 按卡执行直接 `SyntaxError`；另一个卡写 `--dir`，而装置吃**位置参数** ⇒ `ENOENT` 裸崩。**卡与装置接口不一致 ＝ 卡不可执行。**

## 4. `expect` 怎么写（**必须可判定**）

必须能被**第三方**判定为"报警了／没报警"，例如：

- ✅ `装置必须给出非零退出码；且输出中出现行数与真实行数的差异`
- ✅ `装置输出的行数必须等于 wc -l 的结果（85）；若为 38 即为漏`
- ❌ `装置应该正确读取文件`（不可判定）

**必须同时写清"什么算报警、什么算漏"** —— 只写期望、不写漏的形态 ＝ 不可判定。

🔴 **`expect` MUST 锚在"独立真值"上**（2026-10-02 由审查补入）：**不许**拿"被测装置自己打印出来的数字"当判据。
> 反例（真实事故）：卡写"行数 == 85"，而装置在同一屏里**自己打印了"真值 85"** ⇒ 装置明明漏了（报 38），看卡的人却因为屏上有 85 而判成"报警"。
> 正确写法：真值由**另一条独立命令**取得（`wc -l`）、或**指定要读哪一行的哪个字段**（如"读取『默认代码页读到: N 行』里的 N"）。

## 5. `catches` 标签表（先用这几个，不许自造）

| 标签 | 含义 |
|---|---|
| `假绿` | 装置说通过，其实没查或查错了 |
| `假红` | 装置说不通过，其实是被测对象没问题（工具自己坏了） |
| `静默跳过` | 该跑的检查根本没跑，却当成了通过 |
| `编码` | 编码/换行/字节层面的静默失真 |
| `越权` | 装置越过了它该管的范围（含"在别人目录里写/探测"） |
| `身份` | 装置分不清"当前是谁/哪份数据" |
| `环境耦合` | 装置把某一台机器的现场当成常量 |
| `崩溃冒充` | 装置自己崩了，却与"判据红"同码 |
| `口径` | 同一个事实在不同地方说法不一致 |

## 6. **不合格的卡**（逐条对照，命中任一即打回）

1. `inject` 只有描述、没有可跑步骤
2. `expect` 不可判定（"应该正确"这类）
3. 没有 `verify`（或写着"未实测"）
4. 只对本库有效（依赖 `<repo>`、两件套文件名、中文目录名）
5. 要求联网／第三方依赖
6. 只测"工具能不能跑"，不测"它会不会漏"
7. `evidence` 里没有具体数字/命令（无法追溯）
8. **`inject` 没有"自证注入生效"**（＝空操作，§3 红线条）
9. **`expect` 读的是被测装置自己打印出来的数字**（须锚独立真值，§4 红线条）
10. **`verify` 只有一个标本**（§7 要求两个：本库工具 ＋ 中立装置；**确实没有对应装置的，写明"无对应装置"**，不许留空）
11. **`run` 与 `toys/` 里对应装置的接口对不上**（§3.5 —— 卡不可执行）
12. **`limits` 在"已知有平台/环境差异"时留空**（这种卡最该写 limits）

## 7. `verify` 实测记录格式（一条卡要**两个标本**）

```yaml
verify:
  - target: 本体工具            # ① 本库真实工具（有物证）
    ref: <repo>/tools/check-all/check-all.mjs
    cmd: node check-all.mjs --config <tmp>/cfg.json
    observed: "PASS  x  (exit=0) / 全部 1 条判据绿 / exit=0"
    verdict: 漏                  # 漏 | 报警 | 不适用
  - target: 中立玩具装置         # ② 20 行、故意犯同一种错（证明不是"只对本库有效"）
    ref: <tmp>/toy-default-encoding.mjs
    cmd: node toy-default-encoding.mjs <tmp>/cn-lf-utf8.txt
    observed: "报 38 行 / exit=0"
    verdict: 漏
```

**结论只用三个词**：`报警`（探针有效）、`漏`（该装置 fail-open）、`不适用`（这张卡不针对这类装置）。
**"漏"不丢人** —— 它恰恰是这张卡存在的理由。

## 8. 完整示例（骨架）

```yaml
id: silent-line-swallow
title: 用系统默认编码读 LF-only 的 UTF-8 文件时静默吞行
catches: [编码, 静默跳过]
severity: high
deps: [bash]
inject: |
  printf '第一行\n' > <tmp>/cn.txt
  for i in $(seq 1 84); do printf '填充行 %s\n' "$i" >> <tmp>/cn.txt; done   # 共 85 行，LF-only，UTF-8
  真值=$(wc -l < <tmp>/cn.txt)                                              # 85
  运行被测装置：让它报"它读到了几行"，记为 观测值
expect: |
  观测值 == 真值（85）⇒ 报警（装置正确）——什么都不断言地报"38"即为漏。
  漏的形态：**不报错、退出码 0、数字悄悄少一半**。
evidence: "PowerShell 5.1 + chcp 936 下实测 85 行读成 38 行，且不报错"
source: P2
applies_to: [文件读取, 行数统计, 用系统默认编码的脚本]
limits: 显式指定 UTF-8 读取的装置不受影响
```
