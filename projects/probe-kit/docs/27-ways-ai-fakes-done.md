# AI 交付的 27 种「假完成」

> **一句话**：AI 说 "done" 是**主张**，不是**事实**。下面 27 种，是"看起来做完了"的 27 种具体形态 —— 全部来自真实事故（每条都有可复现物证）。
> 每条格式：**现象** → **它怎么骗过检查** → **怎么抓**。
> **给谁**：要验收 AI 交付的人、写检查工具的人、管 AI 代理的人 —— 不需要认识我们，也不需要用我们的工具。
> **怎么用**：每条的「怎么抓」＝把一种**坏情况注进去**，看被测装置**报不报警**；不报警 ＝ 它在这一条上 fail-open（"没查到"被当成"查过了没问题"）。注入步骤全文、可判定的期望、两个标本的实测记录都在对应的卡里。
> 卡里的 `<tmp>`／`<repo>`／`<subject>` 是占位符：你自己的临时目录／你的仓库根／**你被测装置的启动命令** —— 别当真实路径。

## 一、编码与字节层（最安静的一类）

1. **默认编码静默吞行** —— 读 85 行只报 38 行，**不报错**（P2）
   - 怎么抓：造一份 85 行的 UTF-8 LF-only 文件、末行埋一条真漂移（`wc -l` 独立取真值＝85），喂给"逐行扫描且不显式声明编码"的装置 → 报警＝漂移行号 == 85（或明确报"读取/解码失败"）；漏＝行号变小（历史实测 85→38）、不报错、退出码 0。
   - 卡：`p2-default-codepage-line-swallow.yaml`

2. **假设版本** —— 按文档假设的版本走降级路径，字段悄悄丢失仍 OK（P1）
   - 怎么抓：文档写"本机 v16.20.0"、现场实际 v24.19.0（读回文档＋现取 `node --version`，两侧自证不一致），让"按文档写明的版本挑 API"的装置处理含 Set/Date/undefined 的对象 → 报警＝先取现场真实版本或明确报"版本与文档不符"，字段类型不丢；漏＝静默走降级路径（Date 变 string、Set 变普通对象、undefined 字段被丢）且退出码 0。
   - 卡：`p1-assumed-runtime-version.yaml`

3. **PowerShell 标量陷阱** —— 单元素集合退化成标量，判据**静默为假**（P8）
   - 怎么抓：PowerShell 5.1 下造 3 个同一时刻的目录，让集合经管道退化成标量（自证：元素个数＝1、`$times[0]` 取到的是首字符 "1" 而非 "10:39:13"）→ 报警＝集合比较先 `@()` 强制数组，元素个数、取值、判据三者一致；漏＝打印"收集到的时间戳: 10:39:13"看着正常、判据恒 False、静默走"未删除"分支、退出码 0。
   - 卡：`p8-scalar-trap-silent-judge.yaml`

## 二、时间与环境层

4. **沿用文档里的日期** —— 落款写"当时"，不是"现在"（P3）
   - 怎么抓：给会生成带时间戳报告的装置喂一份落款 2026-09-30 的输入文档（`date +%F` 现取现场真值，自证该日期已过期）→ 报警＝报告里的生成时间戳为**现取**时刻（晚于包落款、与 date 现值同日）；漏＝报告时间戳照抄输入文档的日期（历史实测把 09-30 抄进 6 个落款，而当天实为 10-01）。
   - 卡：`p3-doc-date-parroted.yaml`

5. **报告里是一套运行时，跑的是另一套** —— 报的路径根本不存在（P4）
   - 怎么抓：文档写"工具位于 <某路径>"且该路径故意不建（自证 `test ! -e` 成立），现场另有一套可用运行时 → 报警＝装置核对 documented 路径存在性，不存在 ⇒ 显式报错、非 0 退出，绝不"回答一套、跑另一套"；漏＝口径仍说"用文档那套"、实际静默启动现场另一套、退出码 0。
   - 卡：`p4-documented-tool-path-fallback.yaml`

6. **"纯查询"其实物化了** —— 声称只读，实际写了 272 MB（P5）
   - 怎么抓：被检件跑完故意留 `.tmp-leftover/`（先自证残留真的会出现在盘上），喂给自称"只读/纯查询"的装置 → 报警＝装置把"跑完后多出的未跟踪物"如实报出（如 残留 1 处）并计入非 0；漏＝自称 side_effects: none 而盘上多出物化目录（历史实测 7736 个文件／272.1 MB 且忽略规则无覆盖）、退出码 0。
   - 卡：`p5-query-tool-materializes.yaml`

7. **默认值把真实环境焊死** —— 换目录/换人即失效（P27）
   - 怎么抓：把装置**单独**复制进一个陌生目录（自证目录里只有它这一个文件），无参数运行 → 报警＝缺参数报用法错误非 0，或自证失败时大声退出（exit 2 ＋ 逐条列出哪些判据的目录/脚本不存在）；漏＝对写死的作者机器路径 existsSync→false ⇒ 报"未发现交付件 ⇒ 全部合规"、退出码 0。
   - 卡：`p27-baked-default-probes.yaml`

8. **清了磁盘层就宣布完成** —— 运行时还占着（P9）
   - 怎么抓：造两层状态（磁盘 3 条记录＋运行时注册表 3 条，两侧各自自证在场），让装置只清磁盘层 → 报警＝磁盘计数与运行时计数**分开报**，不一致即报"列表还在、内容已没了"并计非 0；漏＝只报磁盘 0 个就宣布"清理完成"、退出码 0（历史实测：删 23 个目录后盘上裸 uuid＝0，list_agents 仍列 22 children）。
   - 卡：`p9-disk-cleared-runtime-alive.yaml`

## 三、覆盖面悄悄收窄（fail-open 的重灾区）

9. **清单项缺字段被记成 PASS** —— 缺字段＝没有意见（P20）
   - 怎么抓：给"读清单逐条执行"的门槛装置喂一项只有 name、缺 cwd/args 的清单（自证：裸 node 读空 stdin exit=0 的漏机制真的在场）→ 报警＝明确报"清单不合法：args 必须是非空数组"、非 0 拒绝执行；漏＝缺字段项被记 PASS (exit=0) ＋"全部 1 条判据绿"，与"真通过"完全同形。
   - 卡：`p20-manifest-missing-field-pass.yaml`

10. **只查"位置"不查"内容"** —— 目录在就算交付了（P10）
    - 怎么抓：造"包内声明的投递位置"（空目录）与"包实际所在目录"（交付物在这）两处（`ls -A` 自证声明位置为空）→ 报警＝装置解析包内声明的投递路径并与实际位置比对，不一致报"声明位置无交付物/包自相矛盾"非 0；漏＝声明的路径打印了却从不拿来核对，声明目录明明是空仍打印 OK、退出码 0。
    - 卡：`p10-declared-delivery-path-unused.yaml`

11. **正则从不命中** —— 且输出无可观测计数（P12）
    - 怎么抓：造"真值最新编号 P10 ＋ 区间声明 P1–P8"的坏声明（`grep -o … | tail -1` 取真值、`cat` 读回坏声明，两侧自证）→ 报警＝区间声明被识别并核对（报"P1–P8 与实际最大号 P10 不符"）且输出带**可观测计数**（"查 1 处编号声明"）；漏＝正则写死"P1" ⇒ 区间一条不匹配 ⇒ 0 命中 ⇒ 打印 OK、退出码 0、无任何计数，与"全都对"长得一模一样。
    - 卡：`p12-range-declaration-never-matched.yaml`

12. **正则写死单条编号** —— 区间声明整个漏掉（P16）
    - 怎么抓：造"代码围栏内 ### P1 示例＋围栏外真实漂移"的文档（`cat -n` 自证第 1–3 行是围栏、第 4 行是围栏外真漂移），喂给对 .md 逐行执行判据、带"历史段"状态机的装置 → 报警＝围栏内的行不参与判据、不推进状态机 ⇒ 围栏后的真实漂移被报出（退出码非 0）；漏＝围栏内标题被当成真 ⇒ 状态泄漏 ⇒ 围栏后漂移整段跳过、OK 退出码 0（历史实测：同一行旧箱名，含围栏 OK exit 0，去围栏即漂移 2 处 exit 1）。
    - 卡：`p16-fence-poisons-state-machine.yaml`（映射表注记②）

13. **只查顶层自测** —— 子目录里那个必定失败的自测根本没跑（P24）
    - 怎么抓：把产出做成嵌套结构——顶层只有 README，test.mjs 藏在 sub/ 且必然失败（先独立跑它自证 exit=1），让"找 test.mjs 并真跑"的验收装置查 → 报警＝递归找到并明报"子目录自测未运行：sub/test.mjs"（计非 0），或直接递归跑它；漏＝只报"自测 未找到 test.mjs"且退出码 0——"没查到"被当成"查过了没问题"。
    - 卡：`p24-nested-selftest-never-runs.yaml`

14. **只读单个文件就下结论** —— 没看调用方（P21）
    - 怎么抓：给审查装置只喂工具本体的行号视图，而调用方文件里门禁实际排在 add **之后**（`grep -n` 自证调用方原文的行号）→ 报警＝装置在拿不到调用方时明说"此结论取决于调用链、需集成层复核"，或主动索取调用方文件并修正结论；漏＝仅凭单文件视图就下结构性断言"恒绿"（历史实测：7 条审查结论里被证伪的正是这一条）。
    - 卡：`p21-review-misses-the-caller.yaml`

15. **只跑一个审查口径** —— 换个标题级别就全瞎（P17）
    - 怎么抓：造一份"漂移躺在 #### 四级标题段内"的文档（自证 #### 与 ### 两种级别都在场）→ 报警＝两家的口径都跑（或明说只跑了一家、覆盖面多大），漂移被任一口径发现 ⇒ 报出且非 0；漏＝只认 ### 级 ⇒ #### 段内的漂移整块看不见 ⇒ "漂移 0 处 ⇒ 审查通过"、退出码 0（历史实测：同题两审查员去重 5 条真缺陷，2 条仅一方独有——单跑任何一家都拿不全）。
    - 卡：`p17-single-reviewer-blindspot.yaml`

16. **无对照的抽查** —— "没查到"被当成"没有问题"（P26）
    - 怎么抓：同构造两份夹具——4 级标题的非法编号 ＋ 3 级标题的对照（自证两份只差标题级别、其余同构）→ 报警＝一红一绿分明：对照变红证明判据活着，4 级不红才坐实"对 4 级失明"（结论可判定）；漏＝只喂 4 级夹具得到 OK exit 0 就下结论 ⇒ 与"正常识别"不可区分（历史实测这个抽查动作连错三次）。
    - 卡：`p26-blind-without-red-control.yaml`

17. **只读代码不跑代码** —— "自审通过"（P25）
    - 怎么抓：造一个 `avg` 手滑多减 1 的目标件，先用独立命令取真值（avg([1,2,3]) = 1，真值应为 2），再让"只读源码做静态扫描"的自审装置审它 → 报警＝装置至少真跑一次目标（探针驱动一跑就现形）或明说"未运行任何目标代码，此为静态结论"；漏＝静态扫描后宣布"自审通过：无问题"，而探针一跑就现形。
    - 卡：`p25-selftest-by-reading-only.yaml`

## 四、判据本身出错（判据也要被审）

18. **判据过宽** —— 噪音淹没真问题（P19）
    - 怎么抓：造"全集声明 P1–P18（合法）＋局部引用 P9–P12（历史叙述）＋最大号 ### P18"各占一行的文档（`cat -n` 自证三行在场）→ 报警＝装置按语义区分两种区间：全集声明末尾须等于全局最大号，局部区间按"区间内每个编号都存在"判——P9–P12 保持绿、P9–P99 这类坏引用才红；漏＝任意区间都被当全集声明 ⇒ P9–P12 被报"与实际最大号 P18 不符"（假红噪音，真问题 0 条；历史同类误报 4 次）。
    - 卡：`p19-local-range-read-as-fullset.yaml`

19. **判据悄悄改松** —— 一整类被跳过（P13）
    - 怎么抓：造五项夹具——真存在/占位符/真不存在/相对存在/相对不存在（两侧自证：该在的在场、该缺的缺失）→ 报警＝恰好报出 2 处（真不存在＋相对不存在）、其余三项不报——双向判据成立，没有哪一类被整类跳过；漏＝只报 1 处或 0 处（如 ../ 相对路径整类被跳过）——"不报了"与"放宽了"在输出上与真修复不可区分，五项夹具才拆得开。
    - 卡：`p13-relaxed-judge-drops-a-class.yaml`

20. **前缀判断缺边界** —— `src` 放行 `src2/x`（P7）
    - 怎么抓：造 `proj/a.txt` 与 `proj2/x.txt` 同入暂存区（自证两文件都在列）→ 报警＝退出码非 0，且明确报出 proj2/x.txt 越界（正确判定＝`f === allow || f.startsWith(allow + '/')`）；漏＝裸字符串前缀判定把同前缀不同目录一起放行，打印"OK 全部在允许范围内"、退出码 0——恰好放行该工具存在的唯一目的所防的东西。
    - 卡：`p7-prefix-scope-without-boundary.yaml`

21. **假设工具配置** —— 换个环境静默拿到另一种输出（P6）
    - 怎么抓：造含中文名文件的仓库且**不配** core.quotepath（用 `-c core.quotepath=true` 做对照，自证八进制转义形态真的在场）→ 报警＝装置显式声明编码（`-c core.quotepath=false` ＋ `-z` 或等价物）：范围内中文文件不误报（红），范围外中文文件以**真实名字**报越界并计非 0；漏＝拿到八进制转义串直接当路径比较 ⇒ 范围内误报（假红）或范围外静默放行（假绿），且与"真的合规"不可区分。
    - 卡：`p6-git-quotepath-assumed.yaml`

## 五、门槛与流程（"跑了但没进门"）

22. **门槛只取第一条判据的退出码** —— 第二条红了照样提交（P18）
    - 怎么抓：给提交门槛装置喂"一绿一红"两条判据的清单（先各自独立跑一遍，自证一绿一红）→ 报警＝门槛聚合**全部**判据：任一非 0 ⇒ 拒绝提交/退出码非 0，且点名是哪条红了；漏＝只取判据 1 的退出码（=0）⇒ add＋commit 照走、整体退出码 0——判据"跑了但没进门"等于没跑（历史实测：漂移 2 处 exit 1 却已 commit，同日复发第二次，之后才工具化）。
    - 卡：`p18-gate-hangs-one-check-only.yaml`

23. **临时件混进提交** —— 消息文件写在 add 面内（P22）
    - 怎么抓：把 `_commit-msg.txt` 造在 add 面**之内**（自证它与正式文件都以 ?? 在列、未被忽略），让执行/模拟 `git add -- proj` 的流程装置跑 → 报警＝装置在 add 前把"add 面内的临时件"报出来（或 add 面外移/先删再 add），提交历史不含它；漏＝add 抓的是那一刻盘上的字节 ⇒ 临时件以 create mode 进历史，事后删本地文件也只留"创建又删除"的痕迹。
    - 卡：`p22-tempfile-inside-add-face.yaml`

24. **平铺箱子同名覆盖** —— 后一单顶替前一单（P23）
    - 怎么抓：两单同名 test.mjs 先后投进同一个平铺收件箱（每次投完 `head -1` 自证：第一次在场、第二次已被顶替）→ 报警＝投放前查同名：目标已存在 ⇒ 停下报"同名冲突，勿覆盖"并计非 0（或按任务号分层存放）；漏＝无重名检查、无告警，后一单静默顶替、退出码 0（历史实测：上一单 test.mjs 12645 B 被顶成 9981 B——零损失纯属归档副本兜底的侥幸，不是设计）。
    - 卡：`p23-flat-inbox-silent-collision.yaml`

25. **归档用 Force** —— 覆盖上一单且报"0 冲突"（P14）
    - 怎么抓：先放一份"上一单的既有报告"（`ls -l` 记下写入前字节），让装置往**同一路径**写输出 → 报警＝目标已存在 ⇒ 装置拒绝/改名/明确提示（打印"目标已存在"并计非 0），旧内容保得住；漏＝无任何提示静默覆盖：旧文件字节被整体换掉、工具照常退出 0（历史实测 Move-Item -Force 覆盖上一单同名件全程无报错，幸有归档副本才零损失）。
    - 卡：`p14-archive-overwrite-no-check.yaml`

26. **夹具建在脚本目录之外** —— 环境错记成用例失败（P15）
    - 怎么抓：用一个**文件**堵死夹具根（其下 mkdir 必失败），另备一份可写对照（自证：被堵根 mkdir exit 非 0、对照根 exit 0）→ 报警＝夹具建不成 ⇒ 装置显式报"环境错误/夹具不可建"并计非 0，与"用例失败"清楚分开；漏＝夹具建不成不预检、静默继续 ⇒ 全部用例报失败（历史实测 pass=1 fail=13，全是 EPERM mkdtemp）——环境问题伪装成"13 条用例失败"。
    - 卡：`p15-fixture-outside-scriptdir.yaml`

27. **崩溃冒充判据红** —— 未捕获异常，退出码与"真失败"同形（一条实测）
    - 怎么抓：按探针卡契约 §5「崩溃冒充」标签的口径（装置自己崩了，却与"判据红"同码）——故意让被测装置崩：喂一个它读不了的文件、或堵死它要写的路径，然后看退出码与输出形态：**真判据红必须点名"哪条判据、什么漂移"；崩溃只有裸堆栈** ⇒ 两者必须用不同的退出码段或输出前缀分开，否则崩一次就冒充一次"判据红"。⚠️ 本条在 27 张卡中**无专属标本**（见映射表注记③），此抓法按契约口径另行给出。

## 我们的做法与局限

1. **探针卡是我们手工写的，覆盖面有限**：27 张卡全部来自我们自己 27 次真实事故的复盘（每张卡的 `evidence` 就是那次事故的物证），覆盖面＝我们踩过的坑，**不是"AI 假完成"的全集**；没踩过的骗法这里没有，新坑出现要补卡。每张卡的 `limits` 字段写明"什么情况下这张卡不适用"，照卡执行前先读它。
2. **被审对象本身就是扫描器时会"自命中"**：判据工具的代码里必然含被检的那些模式（正则、`process.exit`、子进程调用、编码处理……）。拿这些卡去审"检查装置"一类的对象时，**别把它源码里出现某模式当成命中**——"代码里出现"与"在这个模式上 fail-open"是两回事，唯一的分辨办法是按卡**注入坏情况看行为**，不是扫它的源码下结论。
3. **我们给的是证据，不是保证**：每张卡的 `verify` 只有两个标本（本库真实工具＋一个故意犯同种错的中立装置）、一次本机实测。换装置、换环境、换版本之后，"报警/漏"的结论不自动成立——以你自己的复跑为准；每张卡 `inject` 末尾有**注入自证**步骤，自证不成立实验即作废（这正是防止"照卡执行却测了个空操作"的那道闸）。
4. **平台差异会让注入变形**：P2 依赖系统代码页、P8 依赖 PowerShell 5.1 的标量语义、P6/P22 依赖 git 行为——同一张卡换平台可能注入不生效或现象不同；照卡执行时先看 `deps` 与 `limits`，注入自证不过就停，别硬跑。
